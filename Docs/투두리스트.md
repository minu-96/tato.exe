## P0 — 마감 전 필수

### ✅ P0-1. 미니게임 카드가 전투에 한 장도 안 들어간다 ⚠️ 설계 기둥 ③ 붕괴

- **증상**: 미니게임으로 얻은 카드(15종)를 덱에 넣어도 전투 덱에서 조용히 빠진다. 대장간 목록에도 안 뜬다.
- **원인**: `BuildRunDeck()`이 카드 id를 찾는 사전을 `starterDeck + rewardPool`로만 만든다
  ([BattleController.cs:168](../Assets/CardGame/Scripts/BattleController.cs#L168)).
  그런데 v0.7에서 `rewardPool`을 **전투 출처 20종으로 좁혔다**
  ([CardGameBuilder.cs:49](../Assets/CardGame/Editor/CardGameBuilder.cs#L49)).
  예전 주석 "starterDeck + rewardPool이 전 카드를 커버하므로"가 이때 거짓이 됐다.
  `FindCard()`([BattleController.cs:926](../Assets/CardGame/Scripts/BattleController.cs#L926))도 같은 구멍.
- **확인**: `Battle.unity`의 `rewardPool` GUID 20개가 전부 `source: 4`(Combat)임을 대조함.
- **고치는 방향**: 조회를 `CardLibrary.Load().Find(id)`로 바꾼다 (이미 Resources에 39종 전부 있음).
  `CollectionView`는 이미 이렇게 폴백하고 있다.
- **여파**: 기획서 §8의 "미니게임 안 함 19.8% / 함 35.5%" 격차가 **실제 게임에서는 존재하지 않았다.**

### ✅ P0-2. 밭의 생존자 메뉴에서 Space를 누르면 tato.exe 세이브 전체가 지워진다

- **원인**: `GameMenu1` 씬의 `Reset_Button`이 Space 입력에 `resetData` 오브젝트를 켜고,
  그 `Reset_Data.Start()`가 **`PlayerPrefs.DeleteAll()`** 을 부른다
  ([Reset_Data.cs:9](../Assets/ThePotato/Scripts/System/Reset_Data.cs#L9),
  [Reset_Button.cs:11](../Assets/ThePotato/Scripts/System/Reset_Button.cs#L11)).
- **날아가는 것**: 토인 · 보유 카드 · 덱 · 진행 중인 런 · 구매/설치 상태 · 업적 · 해상도 설정 전부.
  미니게임이 단독 게임이던 시절 코드가 통합 후 폭탄이 된 경우.
- **확인**: 두 스크립트 GUID가 `GameMenu1.unity`에 붙어 있는 것 확인.
- **고치는 방향**: 밭의 생존자 키(`TotalCoin`, `HighScore0~9`)만 지우도록 바꾼다.
  같은 이유로 프로젝트 전체에서 `DeleteAll`을 금지어로 두는 걸 권함.

### ✅ P0-3. 나갔다 들어오면 방금 이긴 전투를 또 할 수 있다 — 토인·카드 무한 파밍

- **원인**: 현재 노드 위치(`RunState.Col`)는 **다음 노드를 고를 때만** 전진한다
  ([RunState.cs:196](../Assets/CardGame/Scripts/RunState.cs#L196)).
  전투를 이기고 보상/맵 화면에서 `나가기`(항상 떠 있음, [BattleController.cs:733](../Assets/CardGame/Scripts/BattleController.cs#L733)) 또는 ESC
  → 런처 → GAME START 하면 `Start → EnterNode()`가 **이미 깬 노드를 다시 시작**한다.
- **악용 범위**
  - 일반 전투 반복 → 토인 3~6 + 카드 1장씩 무한
  - **보스 반복 → 초월/전설 카드 무한** (보스 보상 화면에서 나가면 됨)
  - 휴식 노드 반복 → 매번 +29 회복
- **확인**: 코드 경로로 확인 (실행 테스트 아님).
- **고치는 방향**: `RunState`에 `nodeCleared`를 추가해 `Persist()`에 같이 저장.
  `Win()`에서 true, `MoveTo()`/`NextStage()`에서 false. `EnterNode()`는 cleared면 전투 대신 `ShowMap()`.
  보상 화면에서 나간 경우는 → **결정 D-2** 참조.

### ✅ P0-4. 전투 중 나가기 = 공짜 재도전 (손실 채널이 사실상 없다)

- **원인**: 플레이어 체력은 `Win()`에서만 저장된다([BattleController.cs:410](../Assets/CardGame/Scripts/BattleController.cs#L410)).
  죽기 직전 ESC → 다시 들어오면 **전투 시작 시점 체력 + 새 적 + 새 셔플**로 재시작.
- 기획서 §14-1은 이걸 "지금은 실익이 없다(보류)"로 적어뒀는데 **실익이 크다.**
  런 실패(덱 소멸)가 이 게임의 가장 큰 손실 채널인데, 이 구멍 하나로 전부 회피된다.
- **→ 결정 D-1** (어떻게 막을지는 설계 선택)

### ✅ P0-5. ESC 한 번에 두 곳이 반응한다 — 미니게임 일시정지 = 런처로 튕김

- **원인**: `LauncherTransition.Update()`가 런처 밖 모든 씬에서 ESC를 잡아 런처로 보낸다
  ([LauncherTransition.cs:105](../Assets/Launcher/Scripts/LauncherTransition.cs#L105)).
  그런데 미니게임도 ESC를 자기 용도로 쓴다.

  | 씬 | 미니게임 쪽 ESC | 결과 |
  |---|---|---|
  | 늘어나라 인게임 | 일시정지 ([SnakeGameManager.cs:38](../Assets/SnakeGame/Script/SnakeGameManager.cs#L38)) | 정지와 동시에 런처로 — 판 날아감, 보상 없음 |
  | 밭의 생존자 InGame0~6 | 일시정지 (`PauseManager` 프리팹의 `Pause_Game`) | 동일 |
  | 밭의 생존자 GameMenu1 | 타이틀로 (`Exit.cs`) | `LoadScene` 두 개가 경쟁 |
- **고치는 방향(택1)**: ⓐ 비상구 키를 ESC 말고 다른 키(예: F10)로 ⓑ 자체 ESC가 있는 씬은 전역 ESC 제외 목록에 넣기.
  ⓐ가 한 줄이라 빠르다. 전투 씬 ESC는 D-1 결정과 같이 정리.

### ✅ P0-6. 미니게임 보상이 두 번 지급될 수 있다

- 늘어나라 `GameOver()`에 가드가 없다([SnakeGameManager.cs:86](../Assets/SnakeGame/Script/SnakeGameManager.cs#L86)).
  벽 충돌(트리거)과 몸통 충돌(`Move`)이 같은 프레임에 겹치면 `Grant`가 2번.
- 밭의 생존자는 **농부마다** `OnTriggerEnter2D`에서 `Grant`를 부른다
  ([FarmerMovement.cs:123](../Assets/ThePotato/Scripts/Farmer/FarmerMovement.cs#L123)).
  농부 둘이 동시에 닿거나, `LoadScene`이 다음 프레임에 적용되기 전 트리거가 한 번 더 오면 중복.
- 모아모아는 `GameState` 가드가 있어서 안전 — 같은 패턴으로 맞추면 된다.
- 근본책: `TatoReward.Grant` 쪽에 "이번 판 이미 지급" 플래그(씬 로드 시 리셋)를 두면 미니게임 코드를 믿지 않아도 된다.

### ✅ P0-7. 밭의 생존자를 끝까지 살아남으면 카드를 못 받는다

- `Grant`는 **잡혔을 때만** 불린다. `InGame6` 종료 버튼은 `GameOver1/3`으로 바로 넘어간다
  (`InGame6.unity:1960` 부근). 7라운드 완주(최고 성과) = 0장, 7라운드에서 잡힘 = 3장.
- 참고: 기록이 `SceneNumber()+1`이라 "잡힌 라운드"까지 생존으로 친다. 의도라면 OK, 아니면 +1 제거.

# 피드백

## 잘한 점

- **설계 기둥 4개가 "왜"와 함께 적혀 있다.** 각 규칙이 어떤 문제를 막으려고 생겼는지(덱 잠금 → 나이 회피, 소멸 → 무한 콤보,
  회복 배제 → 체력 예산) 남아 있어서, 나중에 규칙을 바꿀 때 무엇이 같이 무너지는지 추적할 수 있다. 이건 흔치 않다.
- **수치를 추측이 아니라 시뮬로 정했다.** "회복 5종 → 완주율 28%→99%", "휴식이 최대체력의 80%여야 분포가 성립" 같은 발견은
  손으로 플레이해서는 절대 못 찾는다. 북돋우기 무한 콤보를 시뮬이 멈춰서 찾은 것도 좋은 사례.
- **아트 늦게 와도 안 깨지는 구조.** `UiKit.Apply` + `BattleTheme` 슬롯 + 9-slice 자동 전환. 추석으로 아트가 밀린 지금 상황에 정확히 맞는 선택.
- **데이터 외부화가 일관적이다.** 카드·적은 SO, 보상 규칙은 `CardLibrary` 인스펙터, 미니게임 연동은 `TatoReward.Grant` 한 줄.
  미니게임 쪽 수정이 한 줄로 끝나게 만든 다리 설계가 깔끔하다.
- **2층 카드 스키마**(원본 SO / 인스턴스)와 **런타임 복제로 강화·싹 적용** — 에셋 오염 없이 개별 카드 상태를 다룬다.
- 씬 전환 연출(가린 뒤 해상도 변경), 상주 오브젝트 정리 등 **통합 과정의 지저분한 문제를 정면으로 처리**했고, 그 이유까지 문서에 남겼다.

## 설계 피드백

### 1. 기둥 ③(미니게임 = 카드 공급)이 지금 게임 안에서 체감되지 않는다

P0-1 버그 때문에 미니게임 카드가 전투에 안 들어가서, **플레이어 입장에선 미니게임을 할 이유가 없다.**
그리고 이 기둥을 뒷받침하는 수치(19.8→35.5%)는 29종 시절 측정이다.
버그를 고친 뒤 재측정해서 격차가 여전히 의미 있게 나오는지 확인하는 게 마감 전 가장 가치 있는 작업이라고 본다.

### 2. 기둥 ④(저장공간)는 현재 UI일 뿐, 선택을 강요하지 않는다

- 전부 깔아도 480/500MB — 공간 압박이 없다
- 삭제는 공짜이고 언제든 되돌릴 수 있고, 삭제해도 카드가 그대로 쓰인다
- 판매할 수 있는 게임이 밭의 생존자 1개뿐

즉 "무엇을 설치할지가 곧 어떤 축을 쓸지"라는 문장이 지금은 성립하지 않는다. 문서도 "게임이 늘면"이라고 미루고 있다.
프로토타입에서 이 기둥을 **보여주고 싶다면** 선택지:

| 안 | 효과 | 비용 |
|---|---|---|
| 총량을 줄임 (예: 300MB → 미니게임 2개만) | 즉시 선택 압박 | 수치 하나 |
| **미설치 게임의 카드는 덱에 못 넣음** | 저장공간 ↔ 덱빌딩이 직접 연결 (가장 강력) | 덱 검증 로직 추가 |
| 재설치에 토인 비용 | 삭제가 가벼운 결정이 아니게 됨 | 적음 |

### 3. 기둥 ①(수명)은 데모 시간 안에 드러나기 어렵다

일반 카드 수명이 3~5런이고, 한 런이 24전투다. 처음 해보는 사람이 싹·썩음을 보려면 **풀 런을 3번 이상** 해야 한다.
데모·발표에서 이 기둥을 보여주려면 "처음부터 수명 1~2런 남은 카드 몇 장을 주는" 온보딩이나 데모 세이브를 고려해볼 만하다.

### 4. 에너지 2 / 드로우 5 — "흐름" 카드의 가치가 낮다

39장 중 30장이 1코스트라 매 턴이 사실상 "5장 중 2장 고르기"다. 이미 손패가 남아도는데
드로우 카드(손질·연쇄 파종·굴착·고랑 파기·자리잡기·흙 고르기·씨감자)가 7종이나 된다 — 전투 출처 카드의 역할로 정한
"흐름"이 에너지 없이는 헛돈다. 에너지 카드(북돋우기·한 숨 돌리기)는 소멸이라 드물다.
시뮬에서 드로우 카드의 채택률/기여도를 한번 뽑아보면 판단이 설 것 같다.

같은 이유로 **대장간 − 강화(코스트 −1)가 + 강화보다 압도적일 가능성**이 크다. 1코 카드를 0코로 만들면 행동 경제가 +50%다.
시뮬의 "강화 50%"가 +/− 어느 쪽을 가정했는지 확인하고, 둘을 나눠 재보길 권한다 (D-5와 연결).

### 5. 토인 경제와 시뮬 가정이 연결돼 있지 않다

- 일반 전투 3~6토인, 1스테이지 대장간 전까지 6전투 → **평균 27토인인데 강화는 30**. 새 세이브의 첫 대장간에서는 대부분 아무것도 못 한다
- 풀 클리어 런 수입이 대략 21×4.5 + 3×20 ≈ **155토인 ≈ 강화 5회**
- 반면 시뮬 기준점은 "강화 50% / 100%" — 이게 실제 수입으로 도달 가능한 수준인지 대조가 필요하다
- 미니게임 카드 판매(장당 5~10토인)가 토인 파밍 루트가 될 수 있다. 의도인지?

### 6. 패배의 무게

패배 시 덱의 비귀속 카드 전부 소멸 + 모든 카드가 런마다 늙음 + 표준 완주율 약 30% →
**대부분의 런이 "덱 전멸"로 끝난다.** 로그라이트로서 의도된 긴장일 수 있지만, 수명 시스템이 이미 카드를 소모시키고 있어서
손실이 양쪽에서 오는 구조다. P0-4가 막히면 플레이어가 처음으로 이 무게를 실제로 느끼게 되니, 그때 체감을 꼭 확인해보길.

## 코드·작업 방식 피드백

- **통합 경계에서 버그가 난다.** 이번 P0 7개 중 5개가 "원래 따로 돌던 것이 합쳐진 자리"다
  (단독 미니게임의 DeleteAll·ESC, 보상 풀 축소가 덱 조회를 깨뜨림, 런 저장 추가가 재진입 경로를 만듦).
  규칙을 하나 바꿀 때 **그 값을 읽는 쪽을 전부 grep**하는 습관이 가장 싸게 막는 방법이다.
- **"한 곳에서 막는다"를 조금 더 밀어보자.** 덱 잠금은 `TrySetInDeck` 한 곳이라 좋았는데, 덱을 바꾸는 다른 경로(`AddCard`, `TopUpDeck`, `DestroyBySource`)는 잠금을 안 거친다.
  보상 지급도 마찬가지 — 중복 지급 방지를 미니게임 3곳이 아니라 `TatoReward` 한 곳에서 하면 새 미니게임이 와도 안전하다.
- **런처 → 게임 → 런처 왕복 테스트 체크리스트**가 있으면 좋겠다. 이번 P0 중 3개(재진입 파밍, 공짜 재도전, ESC 충돌)는 전부 "나갔다 들어오기"에서 나온다.
- **문서가 코드보다 빨리 낡는다.** 카드목록.md처럼 코드에서 뽑는 문서가 가장 안 낡는다.
  구현현황의 표(카드 수, 파일 목록, 보상 풀 크기)도 같은 익스포터에서 뽑는 걸 고려해볼 만하다.

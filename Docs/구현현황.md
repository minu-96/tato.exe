# tato.exe 구현 현황

> 기준: [통합 기획서 v0.7](기획서.md) + 적 설계 문서
> 이 문서는 **무엇이 어떻게 구현돼 있는지**를 다룬다. 설계 의도·근거는 기획서 참조.
> 범위: 런처 셸 · 씬 전환 · MVP 전투 코어 · 런(맵) 구조 · 덱/컬렉션 · 대장간 · 아트 적용 구조

## 1. 한눈에 보기 — 현재 돌아가는 루프

```
[런처]  홈 GAME START
   │   (DOS 로딩 연출 + 해상도 전환)
   ▼
[전투 씬]  1노드 ─ 2노드 ─┬─3─┬─4… ─ 7 대장간 ─ 8 ─ 9 휴식 ─ 10 보스
   │                     └───┘  (분기 · 노드 직접 선택)
   │   전투 승리 → 보상(토인 + 카드 3장 중 1택) → 맵으로
   │   보스 격파 → 다음 스테이지(배경 전환) → … → 3스테이지 보스 = 런 클리어
   │   패배      → 인게임 덱 소멸(귀속 제외) → 런 종료
   ▼
[런처]  토인·감자창고·덱 수치가 갱신되어 이어짐
```

## 3. 런처

### 탭 구성 (기획서 §3 좌측 메뉴)
| 탭 | 상태 |
|---|---|
| 홈 | 로고 + GAME START → 전투 씬 |
| 미니게임 | 게임 타일 4개 (각 GAME START → 해당 미니게임) |
| 감자창고(컬렉션) | 등급 필터 + **타입 필터** + **이름 검색** + **정렬 6종** + 세로 스크롤 + 덱 구성 + 새 카드 빨간 점 |
| 상점 | 대표 타일(tato.exe 고정) + 미니게임 구매·판매 |
| 패치노트 | 버전별 변경 사항 목록 |
| 업적 | 업적 15종 — 달성/미달성 구분 + 진행도 |
| 설정 | 런처/메인 게임 해상도 드롭다운 + 메인 게임 전체화면 토글 |

### 상단 HUD (§3)
| 칩 | 표시 |
|---|---|
| Chip_TOIN | 토인 보유량 |
| Chip_Basket | 런 덱 장수 |
| Chip_Storage | 감자창고 보유 장수 |
| Chip_Stage | 최고 도달 스테이지 (`2 / 3`) — PlayerPrefs 저장 |
| Chip_Profile | 닉네임 `멀쩡한 감자농부` (고정. 입력 시스템은 나중에) |

`PlayerData.Changed` 이벤트로 값이 바뀌면 즉시 갱신. 칩은 이름으로 찾아 바인딩하므로 배치를 옮겨도 따라감.

### 구조 원칙
- Canvas는 Overlay, CanvasScaler 1280×900 기준
- 콘텐츠는 ScrollRect + Viewport(RectMask2D) + Content(LayoutGroup)
- 카드/타일은 GridLayoutGroup이 배치 → 개수가 바뀌어도 자동 정렬

### 감자창고 — 필터 · 검색 · 정렬

카드가 수십 장으로 늘어나므로 찾는 수단이 네 겹이다. **등급 필터 → 타입 필터 → 이름 검색 → 정렬** 순으로 적용된다.

| 수단 | 동작 |
|---|---|
| 등급 필터 | 전체 / 일반 / 희귀 / 초월 / 전설 (버튼) |
| 타입 필터 | 전체 / 공격 / 방어 / 스킬 / 뿌리 (등급 필터 아래 줄, 코드로 생성 · 아트 전 단색) — 등급 필터와 겹쳐 걸린다 |
| 이름 검색 | 카드 이름 부분 일치, 대소문자·앞뒤 공백 무시. 이름이 없으면 id로도 대조 |
| 정렬 | 드롭다운 6종 |

**정렬 6종**

| 항목 | 기준 | 동점일 때 |
|---|---|---|
| 얻은 순 (최신) — 기본 | instanceId 내림차순 | — |
| 얻은 순 (오래된) | instanceId 오름차순 | — |
| 이름순 | 가나다 (한글 유니코드 = 가나다 순이라 Ordinal 비교로 충분) | 얻은 순 |
| 희귀도 높은 순 | 전설 → 초월 → 희귀 → 일반 | 이름순 |
| 기한 짧은 순 | 남은 런 수 오름차순 — **곧 썩는 카드가 위로** | 얻은 순 |
| 덱에 든 것 먼저 | 덱 포함 여부 | 최신 순 |

- 귀속(시작덱) 카드는 기한이 없어 `기한 짧은 순`에서 맨 뒤로 간다
- 검색 중에는 덱 라벨이 `"감자" 검색 결과 3장 · 런 덱 12장` 으로 바뀐다
- 검색창·정렬 드롭다운은 원래 **그림만 있고 기능이 없었다** — 같은 아트를 쓰는 실제 위젯으로 교체

**새 카드 빨간 점** — 새로 얻은 카드(미니게임·전투 보상)는 카드 오른쪽 위에 빨간 점이 붙는다.
마우스를 올리면 "봤다"로 치고 사라진다. 저장 키 `tato_new_cards` (`PlayerData.IsNew / MarkSeen`)

### 저장공간 시스템 (§4) — 보유와 설치는 별개

런처가 OS 셸이라는 컨셉의 뼈대. **네 가지 동작이 두 축으로 나뉜다.**

| 동작 | 어디서 | 바뀌는 것 | 카드 |
|---|---|---|---|
| **구매** | 상점 | 토인 지불 → 보유 (+공간 되면 자동 설치) | — |
| **판매** | 상점 | 구매가의 **30%** 환급 → 보유 해제 | **소멸** |
| **설치** | 미니게임 탭 | 디스크에 올림 (용량 차지) | — |
| **삭제** | 미니게임 탭 | 설치만 내림, **보유·카드는 유지** | 유지 |

삭제는 저장공간 확보용이라 언제든 되돌릴 수 있고, 판매는 소유를 처분하는 거라
그 게임의 카드가 사라진다(§13.2 손실 채널). 되돌릴 수 없어 두 번 눌러야 실행된다.

| 프로그램 | 용량 | 가격 | 판매가 | 비고 |
|---|---|---|---|---|
| tato.exe (본편) | 180MB | — | — | 항상 보유·설치 |
| 늘어나라 pooo-tato | 85MB | 기본 제공 | 불가 | 처음부터 보유 |
| 모아모아 10tato | 100MB | 기본 제공 | 불가 | 처음부터 보유 |
| 밭의 생존자 | 115MB | 30 토인 | 9 토인 | 유일한 구매 대상 |

**총 500MB 중 480MB** — 지금은 전부 설치해도 들어간다. 저장공간은 게임이 늘어날 때를 위한 틀이다.

**탭 역할 분담**
- **미니게임 탭**: 보유 중인 게임만 타일로 보인다. 실행 · 설치 · 삭제.
  맨 오른쪽 `+ Purchase` 타일을 누르면 상점 탭으로 넘어간다
- **상점**: 구매 · 판매만. 구조는 원래대로 **대표 타일(tato.exe) + 미니게임 2행 그리드**
  - 대표 타일은 **판매 불가 · 위치 고정**(항상 맨 앞) — 에디터 빌더가 만든다
  - 미니게임 타일은 **보유 중인 게임이 앞**에 오고, 같은 묶음 안에서는 싼 것부터

> 기본 제공 두 게임은 가격이 0이라 판매가도 0이 되어 **판매 대상에서 제외**했다.
> 판매 기능이 의미를 가지려면 살 수 있는 게임이 더 필요하다.

### 업적 (15종)

조건을 코드로 판정하고 달성 여부만 저장한다. **한 번 달성하면 조건이 깨져도 유지된다**
(카드를 팔아도 업적은 남는다). 카운터는 실제 게임 이벤트에서 올린다:

| 카운터 | 올리는 곳 |
|---|---|
| 런 시작 · 카드 썩음 | `BattleController.Start` (새 런) |
| 전투 승리 · 보스 처치 | `BattleController.Win` |
| 런 클리어 | `BattleController.ShowRunClear` |
| 대장간 강화 | `PlayerData.TryUpgrade` |
| 미니게임 플레이 | `TatoReward.Grant` |

## 4. 씬 전환 시스템

미니게임마다 해상도가 달라 창 크기가 바뀌는 경우의 시퀀스를 구현.

```
① 오버레이 페이드 인 (0.3초) — 화면을 완전히 가림
② 가려진 뒤 Screen.SetResolution      ← 창이 튀는 게 안 보임
③ 2~3프레임 대기 (리사이즈 완료)
④ LoadSceneAsync(allowSceneActivation = false)
⑤ 최소 표시 시간(0.7초) + 로드 완료 → 씬 활성화
⑥ 페이드 아웃
```

- 오버레이는 DontDestroyOnLoad 캔버스(별도 씬 아님), 화면 전체 앵커
- 로딩 화면은 기획서의 부팅 DOS 연출과 통일 — `Launching 밭의_생존자.exe ...` + `[████░░░░]`
- 폰트: DOSGothic.ttf

### 화면 해상도 — 게임별로 따로 (§3·v0.6 §5 해상도 정책)

**아트 비율이 게임마다 다르다.** 하나의 해상도를 전부에 강요하면 어느 하나는 반드시 어긋난다.
그래서 대상별로 자기 비율의 목록을 갖고 따로 기억한다.

| 대상 | 아트 비율 | 고를 수 있는 해상도 | 기본값 | 전체화면 |
|---|---|---|---|---|
| 런처 | 1280×900 (64:45) | 1024×720 · **1280×900** · 1536×1080 | 1280×900 | ✗ (창 셸 컨셉) |
| 메인 게임 (Battle) | 16:9 | **1280×720** · 1600×900 · 1920×1080 | 전체화면 | **✓ 토글** |
| 늘어나라 | 1024×768 (4:3) | 800×600 · **1024×768** · 1280×960 | 1024×768 | ✗ |
| 모아모아 | 16:9 | **1280×720** · 1600×900 · 1920×1080 | 1280×720 | ✗ |
| 밭의 생존자 | 16:9 | 1280×720 · 1600×900 · **1920×1080** | 1920×1080 | ✗ |

**어디서 바꾸나**

| 대상 | 조작 위치 | 방식 |
|---|---|---|
| 런처 · 메인 게임 | 런처 **설정** 탭 | 드롭다운 (해상도) + 토글 버튼 (메인 게임 전체화면) |
| 미니게임 3종 | **각 게임 타이틀 화면** 우측 하단 | `◀  1024×768  ▶` — 화살표 두 개뿐 |

미니게임 해상도를 런처 설정에 넣지 않은 이유: 게임마다 비율이 달라 한 목록에 못 모으고,
"그 게임 안에서 그 게임 설정을 만진다"가 조작으로도 가볍다.

**구조 — 씬 배선 없음**

| 파일 | 역할 |
|---|---|
| `Scripts/DisplaySettings.cs` | 대상별 해상도 목록·저장·적용 (PlayerPrefs) |
| `Scripts/DisplayBootstrap.cs` | 씬 이름 → 대상 매핑. 씬이 뜰 때마다 자동 적용 |
| `Scripts/MinigameDisplayStepper.cs` | 미니게임 타이틀의 ◀▶ 위젯 (자동 생성) |
| `Scripts/DisplaySettingsView.cs` | 설정 탭 드롭다운·토글 배선 |

- `[RuntimeInitializeOnLoadMethod]` + `sceneLoaded` 구독이라 **어떤 경로로 씬이 로드되든** 걸린다
  (런처 전환 · 미니게임 내부 씬 이동 · 다시하기 전부)
- 씬 전환 시에는 화면이 가려진 동안 목적지 씬의 해상도로 바꿔서 창이 튀는 게 안 보인다
- 빌드 씬 20개 전부 매핑 확인됨 (기본값으로 새는 씬 없음)
- **에디터에서는 적용하지 않는다** (Game뷰는 실제 창이 아님) — 빌드에서만 확인 가능
- `GameLaunchButton`의 width/height/fullscreen 필드는 참고용으로만 남아 있다

### 런처로 복귀 (왕복)

`LauncherTransition.ReturnToLauncher()` — 나갈 때와 같은 DOS 연출을 역방향으로 쓴다.

```
① 페이드 인 (화면을 가림)
② 미니게임이 남긴 상주 오브젝트를 비활성화 + timeScale 복구   ← 새로 추가
③ Screen.SetResolution(1280×900)  — 런처 기준으로 복원
④ Launcher 씬 로드
⑤ 상주 오브젝트 파괴 (새 씬이 올라온 뒤)
⑥ 페이드 아웃
```

| 나가는 곳 | 호출부 |
|---|---|
| 늘어나라 타이틀 | `TitleManager.Quit()` |
| 모아모아 게임오버 | `MoaMoaGameManager.QuitGame()` |
| 밭의 생존자 메뉴 | `ExitGame.QuitGame()` |
| 전투 씬 | `BattleController.ExitToLauncher()` |
| **어느 씬이든** | **ESC 키** — 단, 런처 씬과 ESC를 자기 용도로 쓰는 씬(늘어나라 인게임·밭의 생존자 라운드·메뉴)은 제외 |

> ESC 예외가 없던 때는 미니게임에서 ESC로 일시정지하면 **일시정지와 동시에 런처로 튕겨** 그 판과 보상이 날아갔다.
>
> 이전에는 미니게임 3종의 나가기가 전부 `Application.Quit()`이라 **빌드에서 앱이 통째로 종료**됐다.
> 런처가 빌드에 없으면(미니게임 단독 빌드) 기존처럼 종료로 대체된다 — `LauncherTransition.QuitApplication()`.

**상주 오브젝트 정리가 필요한 이유** — 미니게임들이 `DontDestroyOnLoad`로 띄운 싱글톤이
런처로 돌아온 뒤에도 살아남아 화면을 망가뜨린다.

| 오브젝트 | 그냥 두면 |
|---|---|
| `AspectRatioController` (모아모아) | Update에서 16:9를 강제 → 런처 창 1280×900을 매 프레임 1280×720으로 되돌림 |
| `TimeManager` (밭의 생존자) | 사라진 씬의 Text를 참조 → 매 프레임 예외 |
| `Total_Coins` · `RoundStateManager` | 지난 판의 코인·라운드 상태를 다음 판으로 끌고 감 |

### 플레이어 기본 수치
| 항목 | 값 |
|---|---|
| 최대 체력 | 36 |
| 에너지 | 2 |
| 턴당 드로우 | 5 |
| 손패 상한 | 8 |

### 방어 2종 분리 — 코어 훅
- 공격 방어(블록): 공격 피해를 수치만큼 상쇄. 중독은 무시
- 효과 방어(와드): 새로 걸리는 디버프를 건수로 무효화

**방어는 둘 다 턴을 넘겨 누적된다.** (슬더스와 다른 지점 — 감자가 흙을 계속 덧입는 느낌)
예외는 `tempBlock` — 철벽처럼 한 번에 크게 주는 블록만 누적되지 않고 소유자의 다음 턴 시작에 사라진다.
피격 시 `tempBlock`부터 태우고(어차피 사라지므로) 남으면 누적 블록으로 막는다.

> 적 블록도 같이 누적된다. 덕분에 감자벌레 껍질이 **깨질 때까지 서 있게** 되어
> 2페이즈 변신(§적설계)이 비로소 성립한다 — 이전에는 적 턴 시작마다 껍질이 증발해
> 변신 조건에 도달하지 못했다.

### 상태이상 6종
취약(+50% 피해) · 약화(−25% 피해) · 중독(턴 시작 피해, 방어 무시) · 힘 · 민첩 · 재생

### 턴 흐름
```
플레이어 턴 시작 → 에너지 리필 → 임시 블록만 소멸 → 지속효과 틱 → 중독/재생 → 드로우 5
  → 카드 플레이 (에너지 소모)
  → 턴 종료: 취약/약화 −1, 블록불가 해제, 손패 버림
적 턴 → 임시 블록만 소멸 → 지속효과 틱 → 중독/재생 → 인텐트 실행 → 반사 정산 → 패턴 진행
```

### 효과 종류 15종 — 전부 구현됨
| EffectType | 카드 | 동작 |
|---|---|---|
| Damage · Block · EffectDefense · ApplyStatus | 다수 | 기본 |
| DrawPerRemainingEnergy | 연쇄 수확 | 남은 에너지 ×N장 즉시 드로우 (정식은 턴 종료 시 — 근사) |
| **TemporaryBlock** | 철벽 | 이번 턴 한정 블록 (누적 안 됨) |
| **ReflectHalfDamage** | 되받아치기 | 다음 적 턴에 받은 피해의 절반 반사 — 막아낸 몫도 포함, 적 블록 무시 |
| **DisableBlockThisTurn** | 돌진 | 이번 턴 더 이상 블록을 얻을 수 없음 (이미 얻은 블록은 유지) |
| **AmplifyPoisonPerTurn** | 뿌리내림 | 그 적이 중독으로 받는 피해 +N (전투 끝까지) |
| **ApplyStatusForTurns** | 곰팡이 정원 | duration턴 동안 매 턴 status +N (효과 방어가 틱을 먹음) |
| `Heal` · `Draw` · `GainEnergy` | 전투 출처 | 회복 / 고정 드로우 / 이번 턴 에너지 +N |
| `DamageFromBlock` | 흙 던지기 | 누적 방어의 N%만큼 피해 (방어는 유지) |
| `DamageConsumingBlock` | 흙사태 | 누적 방어의 N%를 소모하고, 소모한 만큼 피해 |

> 굵은 5종은 이전까지 `ResolveEffect`의 `default:`에서 조용히 버려져 **카드가 표기와 다르게 동작**했다.
> 특히 뿌리내림·곰팡이 정원은 코스트만 먹고 아무 일도 일어나지 않았다.
>
> ⚠️ 카드 데이터(생성기)를 고친 뒤에는 **`TatoGames ▸ Generate MVP Cards (39)`** 를 다시 실행해야
> SO 에셋에 반영된다. 컴파일이 끝난 뒤에 실행할 것.

### 미니게임 → 카드 수급 (§8 획득처)

미니게임 3종이 판을 끝낼 때 성과에 따라 **그 게임 출처의 카드**를 준다.

| 미니게임 | 기준 | 호출부 |
|---|---|---|
| 늘어나라 pooo-tato | 점수(먹은 개수) | `SnakeGameManager.GameOver()` |
| 모아모아 10tato | 점수(없앤 개수) | `MoaMoaGameManager.EndGameFromTimer()` |
| 밭의 생존자 | 끝까지 버틴 라운드 수 (0~7, 완주 = 7) | 잡힐 때 `FarmerMovement.OnTriggerEnter2D` · 완주할 때 `StartNextRoundManager.StartNextRound` |

**미니게임 쪽 변경은 한 줄이 전부다.** 씬 배선도, PlayerData 참조도 필요 없다:

```csharp
TatoReward.Grant(AcquireSource.Neulteona, score);
```

동작 구조:

```
미니게임 ──Grant(출처, 기록)──▶ TatoReward
                                   │  Resources에서 CardLibrary 로드 (배선 불필요)
                                   │  출처별 규칙에서 기록에 맞는 구간 선택
                                   │  구간의 장수만큼 희귀도 굴려 카드 추첨
                                   ▼
                              PlayerData.AddCard(id, 희귀도)  → 수명도 여기서 결정(§8.1)
                                   │
                                   ▼  게임별 판 수 · 희귀도별 장수를 누적 (tato_reward_pending)
                        런처로 돌아오면 팝업이 한 번 보여주고 지움 (RewardSummaryPopup)
```

| 파일 | 역할 |
|---|---|
| `Scripts/CardLibrary.cs` | 전 카드 목록 + 출처별 보상 규칙. **Resources 폴더**라 어디서든 배선 없이 읽힘 |
| `Scripts/TatoReward.cs` | `Grant(출처, 기록)` · `TakePending()` · `SceneNumber()` |
| `Launcher/Scripts/RewardSummaryPopup.cs` | 복귀 팝업 — 런처를 떠난 동안 한 모든 판을 합쳐 게임별 판 수·희귀도별 장수 |

**무엇을 알려주나** — 카드 이름과 정확한 조건은 알리지 않는다.
- 복귀 팝업: `늘어나라 · 3판 — 일반 2장 · 희귀 1장`. 0장이면 "조금만 더 하면 카드가 나와요"
- 어떤 카드인지: 감자창고의 빨간 점
- 조건: 실행 로딩 화면의 **팁** 한 줄로 대략만 (`GameEntry.tip`, 예: "사과를 많이 먹을수록 … 희귀 카드도 잘 나와요")

**기본 보상 구간** (⚠️ 전부 추정값 — 실제 점수 분포를 보고 인스펙터에서 조정할 것)

| 출처 | 1장 | 2장 (희귀 20~25%) | 3장 (희귀 35~40%) |
|---|---|---|---|
| 늘어나라 | 5점 | 15점 | 30점 |
| 모아모아 | 10점 | 30점 | 60점 |
| 밭의 생존자 | 2라운드 | 4라운드 | 6라운드 |

규칙은 `CardLibrary.asset` 인스펙터에서 바꾼다. 카드 목록은 생성기가 자동 갱신하고,
**보상 규칙은 한 번 채워지면 덮어쓰지 않는다**(튜닝 보존).

> `CollectionView`도 CardLibrary를 폴백으로 참조한다 — 인스펙터의 `allCards` 배선이 낡아도
> 새 카드의 이름·등급이 감자창고에 제대로 나온다.

### 카드 로스터 39종 (§8.3)

| 출처 | 일반 | 희귀 | 축 |
|---|---|---|---|
| 시작덱 (귀속) | 4 | – | 기본 |
| 늘어나라 pooo-tato | 3 | 2 | 공격 |
| 모아모아 10tato | 3 | 2 | 방어 |
| 밭의 생존자 | 3 | 2 | 중독·뿌리 |
| **전투 — 일반·희귀** | **9** | **7** | 흐름 · 하이브리드 · 누적 방어 활용 |
| **전투 — 초월** | – | **3** | 강한 1회성 (전부 소멸) |
| **전투 — 전설** | – | **1** | 감자의 왕 (소멸) |

**메인 게임 카드의 역할** — 세 미니게임이 공격·방어·중독 축을 하나씩 가져갔으므로,
전투 출처 카드는 네 번째 축을 만들지 않고 **축을 잇는 접착제**만 맡는다.

| 이름 | 타입 | 코스트 | 효과 |
|---|---|---|---|
| 흙 던지기 | 공격 | 1 | 2 피해 + 방어의 50%만큼 추가 피해 |
| 손질 | 스킬 | 1 | 카드 2장 뽑기 |
| 북돋우기 | 스킬 | 1 | 에너지 +1 + 카드 1장 |
| 되박기 | 공격 | 1 | 3 피해 + 3 블록 |
| 자리잡기 | 뿌리 | 1 | 민첩 +1 + 카드 1장 |
| 흙 고르기 | 스킬 | 1 | 효과방어 2 + 카드 1장 |
| **흙사태** | 공격 | 2 | 4 피해 + **방어를 모두 소모해 그만큼 피해** |
| 연쇄 파종 | 스킬 | 1 | 카드 3장 뽑기 |
| 감자의 결의 | 스킬 | 2 | 힘 +2 + 민첩 +2 |
| 굴착 | 공격 | 1 | 4 피해 + 카드 1장 |

`흙 던지기`·`흙사태`가 이 묶음의 핵심이다 — **누적 방어를 공격 자원으로 바꾸는** 카드라,
모아모아(방어) 빌드에 승리 수단이 생긴다. 블록 누적이라는 이 게임 고유 규칙의 유일한 payoff다.

> ⛔ **회복 카드는 의도적으로 넣지 않았다.** 난이도 전체가 "24전투 × 고정 체력 예산
> (최대체력 36 + 휴식 29×3)"이라는 누적 소모 위에 서 있어서, 반복 가능한 회복이 들어오면
> 예산 개념 자체가 무너진다.
> **실측**: 회복·재생 5종만 추가해도 표준 플레이 완주율 **28% → 99%**.
> 가장 센 카드 하나(회복 8)를 빼도 90% — 수치 조정으로 막을 수 있는 종류가 아니다.
> 그래서 `StatusType.Regen`은 아직 어떤 카드도 쓰지 않는다(§13 미결).

### 키워드 — 소멸 (§10.3)

`CardKeyword.Exhaust`. 쓰면 **버림 더미로 가지 않아** 이번 전투에서 다시 안 나온다.
그 대가로 평소보다 센 1회성 효과를 준다. 39종 중 **9종**이 쓴다.

> ⚠️ **소멸이 없으면 무한 콤보가 생긴다.** `북돋우기`는 코스트 1에 에너지 +1이라 실질 무료인데,
> 소멸이 없으면 버림 더미로 갔다가 덱이 한 바퀴 돌 때 다시 뽑혀 **한 턴에 무한 반복**된다.
> 시뮬레이션이 멈춰서 발견했다 — 에너지를 되돌려주는 카드에는 반드시 소멸을 붙일 것.

## 6. 데이터 구조

### 2층 카드 스키마 (§8.2)
```
① CardData (SO 에셋)     — 원본 정의. 밸런싱 수치는 전부 여기 (§14.4 하드코딩 금지)
② CardInstance (세이브)  — 보유 카드 1장. 같은 카드도 개별로 다룸
     { instanceId, cardId, bound, upgrade, age, rotAt }
```

### 감자 상태 — 생 / 싹 / 썩음 (§7 · §8.1) — 차별점 1축

**시간축 = 런 수.** **새 런을 시작할 때만** `PlayerData.AgeAll()`이 보유 카드 전부를 한 살 먹인다
(덱에 넣었든 창고에 뒀든 — 쟁여두기 방지). 귀속(시작덱)은 면제라 늙지도 썩지도 않는다.

| 상황 | 런 카운팅 | 덱 편성 |
|---|---|---|
| 새 런 시작 (죽거나 클리어한 뒤) | ✅ +1 | 가능 |
| 전투 중 `나가기` → 런처 → 다시 GAME START | ❌ 이어하기 | **잠김** |
| 런 진행 중 런처에 나와 있을 때 | — | **잠김** |

> **덱 잠금이 핵심이다.** 런이 진행 중(`RunState.Active`)이면 `PlayerData.TrySetInDeck`이
> 한 곳에서 막으므로 어느 UI로도 우회할 수 없다. 이게 있으면 중간에 나갔다 오는 것으로
> 얻을 게 없어서, 나이 회피·손실 회피 구멍이 동시에 막힌다.
> 새 런은 죽거나 클리어해야만 시작되므로, 나이도 그때만 는다.
>
> 대장간의 강화·제거는 **런의 일부**라 그대로 동작한다(§10.8·§10.10).
> 썩은 카드 판매도 덱과 무관해 허용된다.

획득 시 희귀도별 범위에서 수명(`rotAt`)을 한 번 굴려 인스턴스에 고정한다:

| 희귀도 | 수명(런) | 생 | 싹 | 썩음 |
|---|---|---|---|---|
| 일반 | 3~5 | rotAt−1런까지 | 딱 1런 | 이후 |
| 희귀 | 5~8 | 〃 | 〃 | 〃 |
| 초월 | 7~10 | 〃 | 〃 | 〃 |
| 전설 | 10~13 | 〃 | 〃 | 〃 |

- **싹** = 썩기 직전 1런. `sproutEffects`로 효과가 세진다(대략 +2 — 대장간 강화 +3보다 한 단계 아래).
  경고이자 라스트 찬스. **대장간 강화와 겹쳐서** 적용되므로 "싹난 카드를 강화한 그 런"이 최고점이다
- **썩음** = 덱에서 자동 제외, 창고에는 남는다. 감자창고에서 **장당 3토인**에 판매 (희귀도 무관 고정가)
- **창고 표시는 "다음 런 기준"** — 나이를 런 시작 때 먹으므로, 런처에서 보이는 `State`는
  이미 끝난 런의 값이라 한 칸 뒤처진다. 그래서 감자창고는 `NextRunState` · `RunsLeftToPlay`로
  **앞으로 실제로 낼 수 있는 횟수**를 보여준다. "4런 남음"이면 정말로 4번 더 쓸 수 있다

```
창고 "4런 남음" → 1런 사용 → "3런 남음" → 2런 사용 → "2런 남음"
→ 3런 사용 → "싹 · 마지막" → 4런 사용(싹 버프) → "썩음"(사용 불가, 판매만)
```

- `IsSpent`(= 다음 런에 썩음)가 판매·덱편입 판정의 기준이다. 아직 `IsRotten`은 아니지만
  다음 런 시작에 반드시 썩으므로 **두 번 다시 낼 수 없는** 카드 — 바로 팔 수 있게 한다
- 전투 덱을 만들 때 `CardUpgrade.Build(card, upgrade, state)`가 상태와 강화를 함께 얹는다

> 귀속 카드는 썩지 않는 대신 **싹 버프도 못 받는다** — 안전하지만 장기적으로 약한 카드가 된다.

### 런 덱 규칙
- 최소 8장 · 최대 30장
- 시작덱도 덱에서 뺄 수 있음 — 다른 카드로 8장을 채우면 시작덱 없이 진행 가능

- **전투 보상 카드**는 덱에 자리가 있으면 덱으로, 가득(30장) 찼으면 감자창고로 (맵 화면에 안내)
- **미니게임 카드**는 항상 감자창고로 — 덱 편성은 플레이어가 직접. (예전엔 런 도중 미니게임 카드가 진행 중인 덱에 섞여, 패배 시 의도치 않게 같이 소멸했다)

## 7. 런 구조 (맵 / 스테이지)

### 맵 = 노드 그래프 (§11.3, 분기 최대 2)
- 가로 방향, 10열. 열별 노드 수: `1 · 1 · 2 · 2 · 2 · 2 · 1 · 2 · 1 · 1`
- 노드끼리 연결선을 그리고, 선으로 이어진 노드만 클릭 가능
- 2×2 구간은 35% 확률로 교차 → 길이 갈라졌다 합쳐짐
- 색: 지나온 길 초록 / 현재 주황 / 갈 수 있는 곳 파랑(보스 빨강) / 못 가는 곳 회색
- 각 노드에 적 이름(또는 `대장간 / 강화·제거`, `휴식 / +29`)이 미리 표시

| 열 | 내용 |
|---|---|
| 1 | 1스테이지: 흙덩이 고정 (기본 주고받기 교육) · 2·3스테이지: 무작위 |
| 2 | 1스테이지: 밭두더지 고정 (공격 방어 교육) · 2·3스테이지: 무작위 |
| 3~6 | 분기 전투 (그 스테이지 적 중 무작위) |
| 7 | 대장간 |
| 8 | 분기 전투 |
| 9 | 휴식 (체력 +29) |
| 10 | 보스 |

|---|---|---|---|

### 난이도 목표와 실측 (자동 탐색으로 맞춘 값)

> ⚠️ **아래 수치는 전부 옛 구성 기준이다 — 재측정 필요.**
> ① 모든 스테이지에 적 6종이 섞여 나오던 때(09-26부터 스테이지별 구성) ② 미니게임 카드가 전투 덱에서
> 빠지던 버그가 있던 때(09-26 수정 — 시뮬은 이 버그를 모델링하지 않았으므로 시뮬 쪽은 영향 없음).
> 또 표(30.8%)와 본문(표준 35% / 풀강 60%)은 서로 다른 시점의 측정이다. 재측정 뒤 한 값으로 정리할 것.

**설계 기준 = 능력 게이팅** — 1스테이지는 강화 없이, 2스테이지는 대장간 강화 절반,
3스테이지는 강화를 전부 해야 뚫린다. 기준점은 **표준 플레이(강화 50% · 싹 20%) = 완주 30%**.

각 스테이지 통과율 (시드 3묶음 × 4000런):

| 강화 | 싹 | 1스테이지 | 2스테이지 | 완주 |
|---|---|---|---|---|
| 0% | 20% | 91.9% | 32.2% | 9.3% |
| **50%** | **20%** | **99.4%** | **60.0%** | **30.8%** |
| 100% | 20% | 99.8% | 70.9% | 43.5% |

- 1스테이지는 강화 0%로도 98% 통과 — 튜토리얼 역할 유지
- 2스테이지 게이트가 선명하다: 강화 0%면 36%, 절반이면 72%로 두 배
- **전투 보상을 전투 출처 10종으로 좁힌 영향** (표준 플레이 기준)

  | 보상 풀 | 1스테이지 | 2스테이지 | 완주 |
  |---|---|---|---|
  | 전체 25장 (= 미니게임을 충분히 한 경우) | 99.2% | 72.0% | **35.5%** |
  | 전투 출처 10장만 (= 미니게임을 안 한 경우) | 96.2% | 54.1% | **19.8%** |

  **이 격차가 곧 미니게임을 할 이유다.** 완주율이 떨어진 게 아니라,
  19.8%가 바닥이고 35.5%가 천장인 구간이 생긴 것 — 미니게임으로 카드를 모을수록 올라간다.
  (시뮬은 미니게임 수급을 모델링하지 않아 두 끝값만 잰 것이다)
- 3스테이지 게이트: 강화 절반 35.5% → 전부 59.5%. 전투 출처 카드(드로우·에너지)가
  강화와 함께 스케일해서, 이전(31% → 45%)보다 게이트가 선명해졌다
- 기준점이 목표 30%보다 5.5%p 높다. 더 조이면 강화 100%의 천장(59.5%)도 같이 내려가므로
  **"표준 35% / 풀강 60%"** 로 두었다 — 정확히 30%로 맞추려면 S3 배율만 올리면 된다

> 사망 분포(1:2:3스테이지)는 **플레이어 숙련도에 따라 달라지므로 고정 목표로 쓸 수 없다.**
> 강화 0%면 2스테이지에 사망이 몰리고, 강화 100%면 3스테이지로 옮겨간다.

#### 싹/썩음 도입 이전의 측정 (참고)

**목표** — 완주 30% · 사망 70%, 사망 내부 분포 `1스테이지 3 : 2스테이지 27 : 3스테이지 70`

**실측** — 시드 5묶음 × 6000런 = 30,000런

| | 완주 | S1 사망 | S2 사망 | S3 사망 | 사망 분포 |
|---|---|---|---|---|---|
| 목표 | 30.0% | 2.1% | 18.9% | 49.0% | 3.0 : 27.0 : 70.0 |
| **실측** | **30.2%** | **2.1%** | 21.0% | 46.7% | **3.1 : 30.0 : 66.9** |

완주율과 1스테이지는 정확히 일치. 2·3스테이지 분배만 3%p 어긋나는데, 이건 **양자화 한계**다 —
적 수치가 정수로 반올림돼서 2스테이지 배율이 ×1.00일 때 사망 9.2%, ×1.04일 때 21.0%로 건너뛴다.
목표 18.9%가 그 사이 구멍에 빠져 도달할 수 없다. 더 좁히려면 적 기본 수치 자체를 키워
(예: HP 15 → 30) 해상도를 올려야 한다.

**조정하며 알아낸 것**

- 난이도는 **배율보다 최대체력·휴식에 훨씬 민감**하다. 배율만 만지면 곡선이 안 잡힌다
- 1스테이지 사망률은 배율에 극단적으로 민감: ×1.0에서 0%, ×1.2에서 2.4%, ×1.4에서 40%
  → 1스테이지는 ×1.0으로 두고 **최대체력(36)으로** 사망률을 맞췄다
- **휴식이 최대체력의 80%여야 목표 분포가 성립한다.** 회복이 작으면 누적 소모가 사망을
  2스테이지로 앞당겨서, 배율을 어떻게 조절해도 S2:S3가 37:61 / 47:51로 무너진다
  (휴식 30%·40%·50%·80% 전부 실측해서 80%만 27:70을 맞춤)

- 체력은 노드를 넘어 유지 (전투마다 초기화되지 않음)
- **런 상태는 PlayerPrefs에 저장된다** — 맵 구조·위치·스테이지·체력 + "현재 노드를 끝냈는가"·"새 스테이지 첫 노드 고를 차례인가".
  앱을 껐다 켜도 이어서 한다 (v0.6의 "중간 저장 없음"에서 바뀐 부분)
- **전투도 통째로 저장된다** (`BattleSave`, `tato_battle`) — 체력·방어·상태이상·지속효과·적 행동 순서·덱 순서·손패·버림 더미.
  카드를 낼 때마다·턴이 시작될 때마다 저장해서, 언제 나가도 **그 자리에서** 이어진다
- **받지 않은 보상도 저장된다** (`tato_reward`) — 보상 화면에서 나갔다 오면 같은 토인·같은 후보가 다시 뜬다
- 끝낸 노드(전투 승리·휴식·대장간 나가기)는 다시 들어와도 반복하지 않고 맵부터 연다

> 이 저장들이 없던 때의 구멍: 이긴 전투를 나갔다 와서 또 해 보상 무한 파밍(보스면 초월·전설),
> 휴식 반복 회복, 죽기 직전 이탈 → 전투 시작 체력으로 재도전(덱 소멸 회피)

## 8. 보상 (§12.1)

승리 시:
- 토인: 일반 3~6 / 엘리트 12~15 / 보스 15~25 (※ 지금 엘리트 적은 0종 — 표만 있음)
- 카드 선택: **전투 출처 20종**에서만. 미니게임 카드는 그 게임을 플레이해야 나온다(§8)

| 적 | 카드 | 희귀도 가중 |
|---|---|---|
| 일반 · 엘리트 | **3장 중 1택** | 일반 60 / 희귀 40 |
| **보스** | **2장 중 1택** | **초월 75 / 전설 25** |

> **초월·전설은 보스에서만** 나온다 — 일반·엘리트는 후보 풀에서 아예 제외된다.
> 보스는 선택지가 2장뿐이라 등급이 높은 대신 고를 폭이 좁다.
> 런 하나에 보스가 3번이므로 초월·전설은 **한 런에 최대 3장**.
- 선택한 카드는 컬렉션에 인스턴스로 추가되고 런처 감자창고에 바로 반영

## 9. 대장간 (§11.2 · §10.10 · §10.8)

7번 노드. 런 덱 전체를 카드로 펼쳐 보여주고, 카드를 골라 작업.

| 행동 | 비용 | 효과 |
|---|---|---|
| 강화 + | 30 토인 | 피해·블록·효과방어 +3, 상태이상 스택 +1 → 이름에 `+` |
| 강화 − | 30 토인 | 코스트 −1 (최소 0) → 이름에 `−` |
| 제거 | 25 토인 | 컬렉션에서 영구 삭제 (덱 최소 8장 유지) |

- 카드당 강화는 1회 (§10.10)
- 강화는 인스턴스에 기록되어 다음 전투부터 반영
- 전투 덱 생성 시 강화된 인스턴스만 런타임 복제본으로 올림 → 원본 SO 에셋은 불변

## 14. 알려진 제약

- 런 진행은 `tato_run`, 전투는 `tato_battle`, 받지 않은 보상은 `tato_reward` 키에 저장된다 → 앱을 껐다 켜도 이어서 진행
- 세이브 위치는 회사/제품 이름(`TatoGames` / `tato.exe`)으로 정해진다 — 바꾸면 세이브가 새로 시작된다
- 감자창고는 에디터에서 시작덱 프리뷰만 보이고, 실제 보유분은 Play에서 채워짐
- 카드/적 아트가 없어 현재는 placeholder + 단색 폴백으로 표시
- 전투 UI는 기능 확인용 프로그래머 아트 (아트 슬롯은 전부 준비됨)
